# Product-link import

The item editor's collapsed Import from a store panel fetches a user-entered public HTTPS URL on-device. Direct fetching uses no account, proxy, cloud AI, browser cookies or JavaScript execution. The store receives ordinary network information, including the device's public IP address. Anti-bot pages and JavaScript-only metadata can fail; manual entry remains available. HTTP 429 and HTTP 503 with Retry-After trigger shared per-host cooldowns (seconds or HTTP-date; 60 seconds when absent/invalid). Page and image fetches check the cooldown before connecting, and never retry automatically. Cooldowns last for the current app process. Errors remain visible with an explicit Open store in browser action; no cookies or browser data are read back into Hodd. A successful request from another network does not guarantee phone access.

The importer reads bounded HTML with jsoup's charset detection and prefers schema.org Product JSON-LD over Open Graph/page-title fallback. It resolves linked `@id` nodes and ImageObject `contentUrl`/`url`, converts descriptions to plain text, and supports ProductGroup variants with inherited brand/publisher metadata. Explicit mainEntity and matching page/product URLs outrank unrelated recommendations. Tracking parameters do not change page identity. Several equally plausible products open a choice dialog rather than silently selecting the first. Extraction is intentionally bounded (64 scripts, 256 object nodes, limited traversal depth, 16 displayed candidates); it is not a full JSON-LD processor. Deep graphs and uncommon schema encodings may be incomplete.

Review offers field checkboxes for title, brand, explicit publisher, description-to-notes and store price. Existing values are kept. Brand is stored as a brand attribute and never inferred to be a publisher. Store URL, retail price and the time the price was checked are separate evidence attributes, not collection valuations. Aggregate low prices are marked From, and conflicting offers do not produce an invented single price. Existing catalog provenance is retained; an empty provenance tuple can be filled from the product link. Nothing is committed until the item form is saved.

Images are opt-in. Selecting Import product image downloads a bounded JPEG/PNG/WebP, normalizes it through Hodd's EXIF-aware image processing and shows a local preview. Use details is disabled until that image is ready, or the image option is cleared. Accepted images enter the existing photo editor; a current cover is retained and the new image becomes an additional photo when accepted. The 20-additional-photo limit applies. Image failures leave metadata available for review; retry, uncheck the image or cancel the import. Requests block competing save/photo actions, expose Cancel, check coroutine cancellation before publishing results and remove owned staging files on cancel/disposal. Ownership transfers only on explicit acceptance, so late results cannot replace a newer chosen photo. Saved covers are never overwritten by the importer.

Downloads use HTTPS, manual redirects, MIME checks, content/stream size limits (2 MB HTML, 8 MB images), socket timeouts and elapsed-time checks. Each redirect is revalidated against local/private address checks, including IPv6 unique-local and IPv4 shared-address ranges. This DNS preflight is defense in depth, not connection-level DNS pinning. There is no authenticated-store scraping or guarantee that arbitrary pages describe genuine products. Preview is required before applying untrusted site data.

Deterministic tests cover product selection, graph/image references, variants, title/description normalization, ambiguous products, aggregate/conflicting prices, safe image schemes, merge/provenance, pending fetch/image cancellation, field/image opt-in and photo-editor/gallery integration. They use injected sources on a disposable emulator, not live stores or a personal gallery. Physical-device/store compatibility still requires real-world testing. CI validates a nonempty successful Android summary and rejects failure/crash results without fixing the number of tests in YAML.

## Visible browser import (alpha.10)

Open store in Hodd is an explicit, on-device WebView fallback. It displays the current URL and lets the user load/interact with a page before tapping Import this product. JavaScript and first-party store cookies are available in the app's WebView profile; Chrome/external-browser cookies are not copied. WebView cookies/site storage can persist across browser openings. Browsing runs the site's scripts and contacts its subresources, just as opening the store does; collection data is not exposed to the page. No hosted service, AI service, spoofed browser identity or automated challenge solver is used.

The import button reads only the displayed page's bounded JSON-LD (64 blocks, 1 million characters total), selected Open Graph fields and title. It never exports the full page, cookies, form inputs or local collection. Data is passed into the existing parser/product picker/field review. A page title by itself is insufficient, so common challenge/error pages do not become products. Changing pages, closing the browser or disposing the editor invalidates pending results. Parent save/photo actions are blocked while the modal browser is open.

Only public HTTPS navigation is accepted. File/content access, mixed content, third-party cookies, location/camera/microphone permissions, automatic popups and native JavaScript bridges are disabled. Main navigation and intercepted subresources use DNS/address checks; these are preflight checks, not a browser-wide network sandbox (e.g. they do not pin DNS or inspect every redirected subresource/WebSocket). TLS errors are canceled. A missing WebView provider or renderer failure leaves a closeable error, without applying a suggestion.

Images remain opt-in and use the existing bounded direct image downloader after review. WebView cookies are not forwarded to image hosts. A store/CDN may still refuse its image even when the browser reads metadata; uncheck the image to continue. Some stores can refuse WebView too. There is no guarantee of Elkjøp compatibility until verified on a physical device. External-browser opening remains available separately and does not extract its page contents.

Deterministic emulator coverage loads an in-memory HTTPS-origin fixture in the real WebView, executes page JavaScript that creates Product JSON-LD, imports the rendered metadata, checks challenge-page rejection/close behavior, and checks snapshot bounds, escaping and URL rules. These tests contact no live store. The browser screenshot is captured for visual review.
